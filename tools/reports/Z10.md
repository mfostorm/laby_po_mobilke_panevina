# Задание №10. Классы, объекты, инкапсуляция и наследование

## Вопрос 1. Класс и объект

**Класс** — это чертёж дома. В нём описано, из чего дом состоит (количество этажей, цвет стен — поля) и что с ним можно делать (открыть дверь, включить свет — методы). Жить в чертеже нельзя.

**Объект (экземпляр класса)** — конкретный дом, построенный по этому чертежу. По одному чертежу можно построить сколько угодно домов. У каждого свой адрес в памяти и свои значения: один дом покрашен в белый, другой в синий. Изменения в одном доме не затрагивают остальные.

```java
House myHouse = new House();     // построили дом по чертежу House
myHouse.color = "белый";
House neighbour = new House();   // ещё один, независимый дом
```

## Вопрос 2. Инкапсуляция на примере getLastKnownLocation

```java
locationManager.getLastKnownLocation(LocationManager.GPS_PROVIDER)
```

**Смысл утверждения.** Разработчик вызывает метод и получает координаты, но не знает и не должен знать, как они на самом деле получены. Не важно, как спутники передают сигнал, как работает GPS-чип и что делает код внутри Android. Видна только «вывеска» — публичный метод с понятными параметрами и результатом, а реализация скрыта. Поэтому, если спутниковая компания или команда Android изменят внутреннюю логику, вызов останется прежним и наш код продолжит работать.

**Почему это важно для Android-разработчика:**
- приложение не ломается при обновлениях Android и библиотек, если публичный интерфейс не изменился;
- не нужно разбираться в сложных подсистемах (GPS, сеть, камера), чтобы ими пользоваться;
- скрытые данные нельзя испортить по ошибке извне: класс сам следит за своим корректным состоянием.

## Вопрос 3. Наследование: extends AppCompatActivity

```java
public class MainActivity extends AppCompatActivity {
```

**extends** означает «расширяет»: `MainActivity` наследует все доступные поля и методы `AppCompatActivity` и может добавлять свои или переопределять унаследованные (например, `onCreate`).

**Суперкласс** (родительский) — `AppCompatActivity`, **подкласс** (дочерний) — `MainActivity`.

**Почему «не нужно беспокоиться о взаимодействии с существующими возможностями».** Вся сложная работа уже написана и проверена в суперклассе: жизненный цикл экрана, отрисовка, обработка поворота, совместимость со старыми версиями Android. Подкласс получает её готовой и добавляет только своё. Новый код не вмешивается в унаследованный, а лишь использует или дополняет его. Поэтому старое продолжает работать так же, как раньше.

**Практическая польза на примере Button.** `Button` наследуется от `TextView`, а тот — от `View`. Поэтому у кнопки сразу есть текст (`setText`) от `TextView`, а также видимость, размеры, прозрачность и обработка нажатий (`setVisibility`, `setOnClickListener`) от `View`. Разработчикам Android не пришлось писать всё это заново, а нам достаточно знать методы `View` и `TextView`, чтобы работать с кнопкой. Свой виджет можно создать так же — унаследовать `Button` и добавить только новое поведение.

## Вопрос 4. Создание и использование объекта Soldier

```java
Soldier mySoldier = new Soldier();
mySoldier.health = 100;
mySoldier.soldierType = "sniper";
mySoldier.shootEnemy();
```

**Первая строка.** Объявляется переменная `mySoldier` типа `Soldier`. `new` выделяет в памяти (куче) место под новый объект, а `Soldier()` — вызов **конструктора**. Конструктор — специальный метод с именем класса, который подготавливает объект к работе: задаёт начальные значения полей. Если конструктор не написан, Java создаёт пустой конструктор по умолчанию. Ссылка на созданный объект записывается в `mySoldier`.

**Почему mySoldier.health, а не Soldier.health.** `health` — поле экземпляра: оно своё у каждого солдата. Запись `Soldier.health` не говорит, о каком из солдат идёт речь, поэтому для нестатического поля она даёт ошибку компиляции. Через имя класса обращаются только к `static`-членам, общим для всего класса.

**Переменные экземпляра и локальные переменные:**

| | Переменная экземпляра (поле) | Локальная переменная |
|---|---|---|
| Где объявлена | в теле класса, вне методов | внутри метода или блока |
| Сколько живёт | пока существует объект | пока выполняется метод или блок |
| Где видна | во всех методах объекта | только в своём блоке `{ }` |
| Значение по умолчанию | есть (0, `false`, `null`) | нет — нужно присвоить до использования |

**Второй объект mySoldier2.** Его `health` и `soldierType` будут **другими**, то есть независимыми. `new Soldier()` создаёт новый объект со своей копией полей. Сразу после создания у него будут значения по умолчанию (`0` и `null`) или заданные конструктором. Присваивание `mySoldier.health = 100` меняет только первый объект.
