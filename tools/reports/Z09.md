# Задание №9. Рекурсия методов

## Задача 1. Метод sum без базового случая

```java
public static int sum(int n) {
    return n + sum(n - 1);
}
```

**Ошибка:** нет базового случая, то есть условия, при котором рекурсия останавливается. `sum(5)` вызывает `sum(4)`, `sum(3)`, … `sum(0)`, `sum(-1)` и так до бесконечности. Каждый вызов занимает место в стеке, и через несколько тысяч вызовов программа падает с `StackOverflowError`. Ни одно значение так и не будет возвращено.

**Исправление:**

@code код/Recursion.java#sum

Теперь `sum(5)` = 5 + 4 + 3 + 2 + 1 + 0 = **15**.

## Задача 2. Стек вызовов factorial(4)

```java
public static int factorial(int n) {
    if (n <= 1) return 1;          // базовый случай
    return n * factorial(n - 1);
}
```

```
Вызовы (стек растёт):
factorial(4)  → ждёт 4 * factorial(3)
  factorial(3)  → ждёт 3 * factorial(2)
    factorial(2)  → ждёт 2 * factorial(1)
      factorial(1)  → базовый случай, возвращает 1

Возвраты (стек сворачивается):
      factorial(1) = 1
    factorial(2) = 2 * 1 = 2
  factorial(3) = 3 * 2 = 6
factorial(4) = 4 * 6 = 24
```

На пике в стеке одновременно находятся 4 вызова. Базовый случай достигается при `n = 1`. После этого результаты возвращаются в обратном порядке, и каждый уровень завершает своё умножение.

## Задача 4. Метод mystery

```java
public static void mystery(int n) {
    if (n == 0) { System.out.println("Готово!"); return; }
    System.out.println(n);
    mystery(n + 1);
}
```

**Вывод при mystery(3):** 3, 4, 5, 6, 7, … — числа растут, пока не закончится стек, после чего программа падает с `StackOverflowError`. «Готово!» не выводится никогда.

**Проблема:** нарушено правило «каждый рекурсивный вызов должен приближать к базовому случаю». Базовый случай `n == 0`, а шаг `n + 1` уводит от нуля всё дальше (при `n > 0`).

**Исправление:** уменьшать `n` и сделать условие устойчивым к отрицательным числам.
