# Задание №11. Наследование и полиморфизм

## Вопрос 1. Что такое наследование

**Наследование** — механизм ООП, при котором новый класс создаётся на основе существующего и получает его поля и методы (`class B extends A`). Подкласс может добавлять свои члены и переопределять унаследованные методы.

Зачем его используют:
- **повторное использование кода:** общее пишется один раз в суперклассе;
- **расширение без изменения:** готовый класс, например `AppCompatActivity` или `Button`, дополняется своим поведением без правки его исходного кода;
- **иерархия и полиморфизм:** с объектами разных подклассов можно работать единообразно, через тип суперкласса.

## Вопрос 2. Суперкласс и подкласс

**Суперкласс** — общий, более абстрактный класс, от которого наследуют. **Подкласс** — более конкретный класс, который наследует, получает всё доступное от родителя и добавляет своё. Подкласс «является разновидностью» суперкласса.

Пример из жизни: **«Транспортное средство»** (суперкласс) есть у всех — едет, перевозит, имеет скорость. **«Велосипед»** и **«Автобус»** (подклассы) — тоже транспортные средства, но у велосипеда есть педали, а у автобуса остановки и пассажиры.

## Вопрос 3. Какие модификаторы позволяют наследовать

Подклассу доступны члены суперкласса с модификаторами **`public`** и **`protected`**, а также **без модификатора** (default), если подкласс в том же пакете. `private`-члены подкласс напрямую не видит: работать с ними можно только через открытые методы суперкласса, например геттеры и сеттеры.

Класс `Lion`, построенный по тому же принципу:

@code код/Zoo.java ~ class Lion ~ this.hungerLevel

Тип `"Lion"` и начальный голод 5 заданы в конструкторе, а возраст и вес приходят параметрами. Поля `age`, `weight`, `type` и `hungerLevel` в `Lion` не объявляются: они унаследованы от `Animal`.

## Вопрос 5. Метод feed(Animal animalToFeed)

**Почему можно передать Elephant, Lion или Tiger.** Каждый из них наследуется от `Animal` и **является** `Animal`. Переменная типа суперкласса может ссылаться на объект любого подкласса. У любого такого объекта гарантированно есть метод `eat()`, поэтому вызов `animalToFeed.eat()` корректен. Если подкласс переопределил `eat()`, выполнится его версия.

**Это свойство называется полиморфизм** («много форм»): один и тот же код работает с объектами разных классов через общий тип.

## Вопрос 6. Что не так с объявлением класса

```java
private class someClass {
    // здесь идёт реализация класса
}
```

1. **Класс верхнего уровня не может быть `private`.** Допустимы только `public` или отсутствие модификатора (default): `private` такой класс никто не смог бы использовать. Ошибка компиляции: `modifier private not allowed here`. `private` допустим только для **внутреннего** (вложенного) класса.
2. **Нарушено соглашение об именовании:** имена классов пишутся с заглавной буквы — `SomeClass`. Это не ошибка компиляции, но плохой стиль.

## Вопрос 7. Абстрактный класс и интерфейс

| Характеристика | Абстрактный класс | Интерфейс |
|---|---|---|
| Можно ли создать объект (экземпляр)? | Нет | Нет |
| Может ли содержать обычные методы с реализацией? | Да, наряду с абстрактными | По лекции — нет, только объявления методов. С Java 8 — `default`- и `static`-методы |
| Может ли содержать поля (переменные класса)? | Да, любые | Только константы (`public static final`) |
| С помощью какого ключевого слова наследуется / реализуется? | `extends` | `implements` |
| Сколько родительских классов / интерфейсов можно унаследовать? | Один | Сколько угодно |

**Когда выбрать интерфейс.** Когда нужно описать **умение**, общее для не связанных между собой классов, — контракт «что класс умеет делать», а не «чем он является». Например, `View.OnClickListener` может реализовать и `MainActivity`, и любой другой класс. Интерфейс нужен и тогда, когда классу требуется несколько таких ролей сразу: интерфейсов можно реализовать много, а наследоваться можно только от одного класса. Абстрактный класс уместен, если у родственных классов есть общее состояние (поля) и общий код.
