# Задание №8. Область видимости переменных и перегрузка методов

## Задача 1. Ошибки области видимости (ProblematicClass)

```java
for (int i = 0; i < data.length; i++) {
    String item = data[i];
    count++;
}
System.out.println(item); // ошибка
System.out.println(i);    // ошибка
```

- `item` объявлена **внутри тела цикла**, существует только в пределах `{ }` этого блока и пересоздаётся на каждой итерации. После цикла её нет: `error: cannot find symbol`.
- `i` объявлена в заголовке `for`, поэтому её область видимости — только сам цикл. После цикла её тоже нет.
- `count` — поле класса, оно видно во всех методах, ошибки нет.

Исправление: объявить переменные до цикла, если их значения нужны после него.

```java
public void processData(String[] data) {
    String item = null;
    int i;
    for (i = 0; i < data.length; i++) {
        item = data[i];
        count++;
    }
    System.out.println(item);  // последний элемент
    System.out.println(i);     // равно data.length
}
```

## Задача 2. Вызов po.execute(5, 5)

Код **не скомпилируется**: `error: reference to execute is ambiguous`. Оба аргумента имеют тип `int`, точного совпадения нет. Подходят оба метода, и каждому нужно одно расширение `int → double`: в первом для второго аргумента, во втором для первого. Ни один вариант не «точнее» другого, и компилятор не может выбрать. Решение — явно указать тип: `po.execute(5, 5.0)` или `po.execute(5.0, 5)`.

## Задача 3. Класс ScopeErrors

| Строка | Ошибка | Нарушенное правило |
|---|---|---|
| 21 | `sum` используется вне блока `if`, в котором объявлена | Локальная переменная видна только внутри блока `{ }`, где объявлена |
| 26 | `a` используется в `printResult()`, хотя объявлена в `calculateSum()` | Локальная переменная метода не видна в других методах |
| 37 | `i` используется после цикла `for` | Переменная из заголовка `for` существует только внутри цикла |
| 38 | `processed` используется после цикла | Переменная, объявленная в теле цикла, видна только в нём |

Строка 30 (`data = data.toUpperCase();`) ошибкой не является: параметр метода — обычная локальная переменная, и ему можно присвоить новое значение.

Исправленный код:

```java
public class ScopeErrors {
    private int total = 0;
    private int a = 10;                 // a нужна в двух методах — делаем полем

    public void calculateSum() {
        int b = 20;
        int sum = 0;                    // объявляем до if
        if (a > 5) {
            sum = a + b;
            total = sum;
        }
        System.out.println("Сумма: " + sum);
        System.out.println("Общий итог: " + total);
    }

    public void printResult() {
        System.out.println("Результат: " + a);
    }

    public void processData(String data) {
        data = data.toUpperCase();
        String processed = "";          // объявляем до цикла
        int i;
        for (i = 0; i < 3; i++) {
            processed = data + i;
            System.out.println(processed);
        }
        System.out.println("Итерация: " + i);
        System.out.println("Обработанные: " + processed);
    }
}
```

## Задача 4. Перегрузка в OverloadAnalyzer

| Вызов | Метод | Вывод | Почему |
|---|---|---|---|
| `process(10)` | 1 | `int: 10` | точное совпадение `int` |
| `process(10.0)` | 2 | `double: 10.0` | литерал `10.0` имеет тип `double` |
| `process(10.0f)` | 2 | `double: 10.0` | метода с `float` нет, `float` расширяется до `double` |
| `process(new Integer(10))` | 3 | `Integer: 10` | точное совпадение с `Integer`, распаковка в `int` не нужна |
| `process("10")` | 4 | `String: 10` | точное совпадение `String` |
| `process(10, 20)` | 5 | `int, int: 10, 20` | два `int` — точное совпадение |
| `process(10, 20, 30)` | 6 | `varargs: 10 20 30` | метода с тремя `int` нет, подходит только varargs |
| `process(new int[]{1, 2, 3})` | 6 | `varargs: 1 2 3` | `int...` внутри — это `int[]`, массив передаётся напрямую |

Компилятор выбирает метод в три этапа: сначала точное совпадение или расширение примитивов, затем автоупаковка и распаковка, и только потом varargs. Проверено запуском:

```
int: 10
double: 10.0
double: 10.0
Integer: 10
String: 10
int, int: 10, 20
varargs: 10 20 30
varargs: 1 2 3
```

**analyzer.process(null)** — **ошибка компиляции** `reference to process is ambiguous`. `null` можно передать в любой параметр ссылочного типа: `Integer`, `String` и `int[]` (varargs). Ни один из этих типов не является подтипом другого, поэтому самый «точный» метод выбрать нельзя. Исправление — явное приведение: `process((String) null)`.

**analyzer.process(10.0f)** выведет `double: 10.0`. Метода для `float` нет, а расширение `float → double` выполняется автоматически без потери точности.

**Можно ли добавить public int process(int x)?** Нет. Сигнатура метода — это имя и типы параметров, возвращаемый тип в неё не входит. `process(int)` уже есть (метод 1), поэтому будет ошибка `method process(int) is already defined`. Перегрузка возможна только при другом списке параметров.
