# Задание №12. Анонимные и внутренние классы. Палитра виджетов

## Вопрос 1. Обычный и внутренний класс

Обычный класс объявляется в отдельном файле и существует сам по себе. **Внутренний** класс объявляется внутри другого класса и логически ему принадлежит.

Главное преимущество — **доступ к данным**: (нестатический) внутренний класс видит **все** поля и методы внешнего класса, включая `private`, так, будто это его собственные. Обычному классу пришлось бы передавать ссылку на объект и пользоваться только открытыми методами. Кроме того, внутренний класс можно скрыть (`private`), если он нужен только внешнему классу.

```java
public class MainActivity extends AppCompatActivity {
    private int clicks = 0;

    class Counter {                       // внутренний класс
        void add() { clicks++; }          // напрямую меняет private-поле внешнего
    }
}
```

## Вопрос 2. Добавление созданной кнопки в LinearLayout

Нужно получить ссылку на `LinearLayout` по id и добавить в неё кнопку методом `addView()`. Конструктору `Button` нужен контекст (`this`): `new Button()` без аргумента не скомпилируется.

```java
LinearLayout layout = findViewById(R.id.mainLayout);

Button myButton = new Button(this);
myButton.setText("Новая кнопка");

layout.addView(myButton);   // кнопка появляется на экране
```

## Вопрос 3. Параметр checkedId в onCheckedChanged

`checkedId` — это **id выбранной `RadioButton`**, то есть то же число, что `R.id.…` из разметки. По нему можно сразу узнать, какая кнопка выбрана, сравнивая с `R.id.radioButtonX`. Если сделать `clearCheck()`, приходит `-1` (ничего не выбрано).

Ссылка на сам объект `RadioButton` получается поиском внутри группы:

```java
radioGroup.setOnCheckedChangeListener(new RadioGroup.OnCheckedChangeListener() {
    @Override
    public void onCheckedChanged(RadioGroup group, int checkedId) {
        RadioButton rb = group.findViewById(checkedId);
        if (rb != null) {
            Log.i("Info:", "Выбрано: " + rb.getText());
        }
    }
});
```

## Вопрос 4. Button и Switch

`Button` реагирует на **однократное нажатие**: используется анонимный класс `View.OnClickListener` с методом `onClick(View v)`. Состояния у кнопки нет.

`Switch` — переключатель **с состоянием** «вкл./выкл.». Важен не сам факт нажатия, а новое состояние. Используется `CompoundButton.OnCheckedChangeListener` с методом `onCheckedChanged(CompoundButton buttonView, boolean isChecked)`: параметр `isChecked` сразу сообщает, включён ли переключатель. Тот же слушатель используется для `CheckBox`.

```java
mySwitch.setOnCheckedChangeListener(new CompoundButton.OnCheckedChangeListener() {
    @Override
    public void onCheckedChanged(CompoundButton buttonView, boolean isChecked) {
        if (isChecked) {
            // включён
        } else {
            // выключен
        }
    }
});
```

## Вопрос 5. EditText, CheckBox и Button

Ссылки на `EditText` и `CheckBox` объявляются `final`, чтобы ими можно было пользоваться внутри анонимного класса.

```java
final EditText editText = findViewById(R.id.editText);
final CheckBox checkBox = findViewById(R.id.checkBox);
Button button = findViewById(R.id.button);

button.setOnClickListener(new View.OnClickListener() {
    @Override
    public void onClick(View v) {
        String text = editText.getText().toString();   // текст из поля
        if (checkBox.isChecked()) {                     // состояние галочки
            Log.i("Info:", "Галочка отмечена, текст: " + text);
        } else {
            Log.i("Info:", "Галочка не отмечена, текст: " + text);
        }
    }
});
```

`getText()` возвращает `Editable`, поэтому для обычной строки вызывается `toString()`. `isChecked()` возвращает `true`, если галочка стоит.
