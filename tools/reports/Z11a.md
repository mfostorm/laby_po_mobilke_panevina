# Задание №11. Инкапсуляция и модификаторы доступа

## Вопрос 1. Какую проблему решает инкапсуляция

Без инкапсуляции любой внешний код может напрямую изменить поля объекта и привести его в некорректное состояние: здоровье станет −50, баланс уйдёт в минус. Кроме того, внешний код начинает зависеть от внутреннего устройства класса. Инкапсуляция скрывает данные (`private`) и открывает только методы, через которые с ними можно работать.

Два ключевых преимущества для разработчика класса:
1. **Контроль над данными.** Все изменения проходят через методы (сеттеры) с проверками, поэтому объект всегда в допустимом состоянии.
2. **Свобода менять реализацию.** Внутреннее устройство класса можно переписать: переименовать поля или изменить алгоритм. Пока публичные методы остаются прежними, код, который пользуется классом, не сломается.

## Вопрос 2. protected и доступ по умолчанию (default)

| Модификатор | Тот же класс | Тот же пакет | Подкласс в другом пакете | Остальные |
|---|---|---|---|---|
| `public` | да | да | да | да |
| `protected` | да | да | **да** | нет |
| default (без модификатора) | да | да | **нет** | нет |
| `private` | да | нет | нет | нет |

Принципиальная разница проявляется при наследовании. `protected`-члены доступны подклассу (`extends`), даже если он находится в **другом пакете**. Default-члены видны только внутри своего пакета: подкласс из другого пакета их не унаследует как доступные. В пределах одного пакета оба модификатора ведут себя одинаково.

## Вопрос 3. Почему private ещё не гарантирует скрытость

Видимость члена класса ограничена видимостью **самого класса**. Модификатор доступа класса — более высокий уровень. Если класс объявлен без `public` (default), другие пакеты не видят его вовсе, а значит и его методы, даже `public`. И наоборот: `private` скрывает поле, но если класс `public` и у него есть `public`-геттер и сеттер без проверок, поле фактически открыто. Итог: доступ определяется сочетанием модификатора класса (и пакета, в котором он лежит) и модификаторов его членов.

## Вопрос 4. Как выбирать модификаторы для методов

Принцип — **минимальные необходимые права** (давать как можно меньше доступа). По умолчанию метод стоит делать `private` и открывать его только тогда, когда он действительно нужен снаружи.
- Методы, которые составляют «услуги» класса для внешнего мира, — **`public`** (как `useMeEverybody`). Это контракт класса: его стоит менять как можно реже.
- Вспомогательные методы, детали реализации — **`private`** (как `secretInternalTask`). Их можно свободно переписывать, никто снаружи от них не зависит.
- `protected` — для того, что должны переопределять или использовать наследники, но не все остальные.

Публичные методы обычно сами вызывают приватные: снаружи виден простой интерфейс, а внутренняя кухня скрыта.

```java
public class Robot {
    public void useMeEverybody() {      // открыто всем
        secretInternalTask();
    }
    private void secretInternalTask() { // деталь реализации
        // ...
    }
}
```
